# Архитектура

## Поток данных
React вызывает API FastAPI. FastAPI валидирует сценарий Pydantic-моделями, применяет действие через engine и сохраняет состояние в SQLite. Проектор и пульт читают одно состояние. После сборки React FastAPI раздаёт `/` и `/assets`; отдельный frontend-сервер нужен только при разработке.

## Модули
- `backend/app/models.py`: контракт сценариев и команд, проверка ссылок графа.
- `backend/app/engine.py`: применение действий без HTTP и БД; переходы, выбор, история, ресурсы, таймер.
- `backend/app/main.py`: API, SQLite-транзакции, импорт, выдача статической сборки.
- `frontend/src/main.tsx`: каталог, режимы просмотра, пульт, сетевое состояние и клавиатура.
- `frontend/src/SlideView.tsx`: отображение сценария без привязки к конкретному МК.
- `frontend/src/types.ts`: TypeScript-контракты.
- `frontend/src/style.css`: бело-фиолетовая тема и адаптивная вёрстка.
- `scenarios/toolkit.json`: всё содержание МК 1, включая заметки.

## Состояние занятия
Сценарий копируется при создании занятия. Храним текущий узел, раскрытие выводов, выбранные варианты в порядке выбора, метрики, таймер и историю снимков. Каждая команда включает revision. Транзакция `BEGIN IMMEDIATE` предотвращает потерю действий; при устаревшей revision сервер отвечает 409, клиент обновляет состояние и предлагает повторить действие.

Выбор пересчитывает метрики от исходных значений по текущим сохранённым решениям; повторные нажатия не дублируют эффект. Возврат восстанавливает снимок. Переход через карту добавляет снимок в историю и сохраняет решения предыдущих экранов. История ограничена 300 переходами. Повторный визит к узлу сохраняет выбранный ранее вариант. Для сценариев с многократными платными действиями нужна другая модель событий: текущие эффекты применяются один раз на выбранный вариант узла.

## Будущий МК 2
Для большинства сцен достаточно JSON: choices[].next, slide.next и effects. Переходы с несколькими выбранными вариантами запрещены: у такого экрана только общий next. Для новых уникальных элементов добавьте значение layout в Pydantic-модель и компонент в SlideView, затем тест и описание контракта. Сценарий не исполняет HTML/JS/CSS; текст отображает React с экранированием.

Для голосования с телефонов: добавить сущности room/participant/vote, роль ведущего и токен доступа, состояние open/closed, правила переголосования и ничьей. Подсчитанный результат преобразуется в ту же команду choose. При необходимости заменить polling на WebSocket/SSE, сохранив начальное чтение полного снимка и revision для восстановления связи. Отдельный API аудитории должен исключать заметки ведущего. Текущий audience - режим отображения локального экрана, не граница безопасности.

## Ограничения версии 1
Нет редактора дерева, внешней генерации, QR-кодов, сетевых ролей, произвольных пользовательских компонентов, публикации в интернете. JSON можно импортировать и экспортировать. Метрики являются условными ресурсами, а не вероятностью успеха.
